### 板块 1 · 医学计算器
- 按科室分组，**心内科第一位，内科系统靠前，外科系统靠后**
- 科室内按**常用性从高到低**排序（rank 决定）
- 支持**搜索**、**按分类筛选**、**置顶**
- 覆盖：血流动力学、风险评分、分级量表、公式计算、判读工具

### 板块 2 · 疾病指南
- 同样按科室分组、常用性排序
- **大类疾病下含小类**（如「冠心病」下有稳定型心绞痛、STEMI、NSTEMI、冠脉痉挛）
- 大类上有 **「对比鉴别」按钮**，一键显示旗下所有疾病的诊断要点与鉴别关键
- 每个疾病包含 6 个环节：
  1. 基础知识（定义 + 危险因素 + 流行病学）
  2. 病理生理
  3. 诊断标准（含必要检查与判读、分型分级）
  4. 鉴别诊断（**第一条是同大类内其他疾病的鉴别点**）
  5. 治疗（药物：药名 + 剂量 + 肾功/肝功调整 + 相互作用；非药物治疗；生活方式）
  6. 预后
- 支持**置顶**（疾病与大类都可置顶）

### 置顶
点击条目右侧的图钉图标即可置顶，置顶项会：
- 出现在该科室列表顶部
- 出现在首页「我的置顶」
- 汇总在 `#/pinned` 页面

## 三、构建

> 构建与校验脚本在**项目工作区**的 `scripts/medkit-build/`，不在本安装包内；包里只有运行所需文件。

数据是 JSON，需要编译成 `js/data.bundle.js`（避免运行时多次请求，离线更可靠）。

```powershell
# 1. 校验所有 JSON 是否合法
python scripts\medkit-build\validate_data.py

# 2. 终端内容审计（重复 id、六环节、compare 覆盖、剂量）
python scripts\medkit-build\final_audit.py

# 3. 教材目录覆盖率（466 条逐条比对）
python scripts\medkit-build\toc_check.py

# 4. 编译数据包（自动合并分片、去重、检查排序）
python scripts\medkit-build\build_data.py
```

构建成功会输出类似：

```
bundle -> js/data.bundle.js  5555.9 KB
计算器: 25 科室 / 462 条
指南:   25 科室 / 201 大类 / 607 疾病
计算器科室顺序: cardio → resp → gi → endo → ...
```

**排序规则**由 `data/departments.json` 的 `order` 字段决定：
- 心内科 = 1（强制第一）
- 内科系统 = 2–11
- 平台/急重症 = 12–13
- 外科系统 = 20–31

## 四、本地预览

```powershell
cd medkit
python -m http.server 8000
```

浏览器打开 `http://127.0.0.1:8000/`。

> Service Worker 在 `localhost` 下可用，但手机通过局域网 IP 访问时**不会启用**离线缓存，必须部署到 HTTPS 才能在手机上离线。

## 五、部署到 GitHub Pages

1. 新建仓库，可见性选 **Public**
2. 把 `medkit` 文件夹内的**全部内容**推到仓库根目录
   - 根目录下应该直接看到 `index.html`，不是 `medkit/index.html`
   - `icons`、`css`、`js`、`data` 也要一起推
3. Settings → Pages → Source 选 `Deploy from a branch` → `main` / `/ (root)` → Save
4. 等 1–2 分钟，得到 `https://<用户名>.github.io/<仓库名>/`

所有路径都是相对路径（`./`），放在子目录下也能正常工作。

## 六、装到 iPhone

1. 用 **Safari** 打开部署好的网址（微信/Chrome/夸克等内置浏览器都不行）
2. 底部**分享按钮** → 下滑 → **「添加到主屏幕」**
3. 命名，点「添加」
4. 联网状态下打开一次（灌缓存），之后断网可用

**验证安装是否成功**：从桌面图标打开 → 顶部无地址栏 → 开飞行模式仍能打开。

## 七、更新内容

**改数据后必须做两件事**：

1. 运行 `python scripts\medkit-build\build_data.py` 重新生成 bundle
2. 打开 `sw.js`，把 `const VERSION = 'v1'` 改成 `'v2'`（每次递增）

然后推送。手机上打开 App 会提示「内容有更新 · 刷新」。

> **版本号只改 `sw.js` 里的 `VERSION`**。不要给 `index.html` 里的 `<script src>` 加 `?v=` 查询串——
> 预缓存清单里的路径不带查询串，加了会导致缓存键不匹配，**离线时页面加载不出来**（已踩过这个坑）。

## 八、新增内容

### 加一个计算器条目
在 `data/calc/<科室>.json` 的 `items` 数组里加一条，字段见 `SCHEMA.md`。

### 加一个疾病
在 `data/guide/<科室>.json` 的对应大类 `diseases` 数组里加，字段见 `SCHEMA.md`。

### 加一个新科室
1. 在 `data/departments.json` 加一条（含 `id`、`name`、`short`、`abbr`、`group`、`order`）
2. 新建 `data/calc/<id>.json` 和 `data/guide/<id>.json`
3. 重新构建

## 九、数据纪律

- 内容依据**公开指南、共识与药品说明书**整理，`refs` 字段记录来源
- **不确定的剂量写「遵说明书」「按体重滴定」，不编造精确数字**
- 以**国内指南为主**（中华医学会各分会、中国医师协会、国家卫健委诊疗规范），国外指南补充
- 数值阈值必须可溯源

### 内容局限（如实说明）

1. **本版内容由 AI 批量整理，未逐条联网核对指南原文**。发布前建议对高频条目（心内科 STEMI、房颤抗凝、DKA、脑楼死溶栓等）抽查对照原文。
2. **肿瘤化疗方案**仅写方案名 + 剂量区间，注明「按 CSCO/NCCN 指南与体表面积调整」，未给到具体体表面积下的总量。
3. 部分条目的肾功/肝功调整写的是「遵说明书」而非具体数值，这是有意的保守处理。
4. 肿瘤、风湿、精神等科室的部分药物剂量来自说明书通用方案，未逐条核验。
